# 10.11 API / System Implementation

## Overview
HIREFLOW-AI implements a comprehensive REST API architecture with Express.js backend, providing endpoints for authentication, job management, candidate tracking, interviews, notifications, and activities. The system employs a layered architecture pattern: Routes → Controllers → Services → Repositories → Database.

---

## 1. Architecture Layers

### 1.1 Request-Response Flow

```
┌─────────────────────────────────────────────────────────────┐
│                   React Frontend (Port 5173)                │
│              (Axios HTTP Client + JWT Tokens)               │
└────────────────┬────────────────────────────────────────────┘
                 │ HTTP/REST
                 ↓
┌─────────────────────────────────────────────────────────────┐
│              Express Backend (Port 3001)                    │
├─────────────────────────────────────────────────────────────┤
│ Layer 1: HTTP Routes & Middleware                          │
│  - Authentication Middleware (JWT validation)              │
│  - CORS & Security Headers (Helmet)                        │
│  - Request/Response logging                                │
├─────────────────────────────────────────────────────────────┤
│ Layer 2: Controllers                                        │
│  - Request validation (Zod schemas)                        │
│  - Input transformation                                    │
│  - Error handling & status codes                           │
├─────────────────────────────────────────────────────────────┤
│ Layer 3: Services                                           │
│  - Business logic                                          │
│  - Complex operations (auth, calculations)                 │
│  - Data transformation                                     │
├─────────────────────────────────────────────────────────────┤
│ Layer 4: Repositories                                       │
│  - Data access abstraction                                 │
│  - Database queries (parameterized)                        │
│  - Query optimization                                      │
└────────────────┬────────────────────────────────────────────┘
                 │ SQL
                 ↓
┌─────────────────────────────────────────────────────────────┐
│         MySQL Database (Port 3306)                          │
│  - Connection pooling (min: 2, max: 10)                    │
│  - InnoDB transactions                                     │
│  - 8 core tables with relationships                        │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Layered Architecture Components

**Routes Layer** (`src/routes/*.ts`)
- Defines HTTP endpoints
- Maps to controller methods
- Applies route-specific middleware

**Controllers Layer** (`src/controllers/*.ts`)
- Receives HTTP requests
- Validates input with Zod schemas
- Calls service methods
- Returns formatted responses

**Services Layer** (`src/services/*.ts`)
- Encapsulates business logic
- Calls multiple repositories
- Performs calculations/transformations

**Repositories Layer** (`src/repositories/*.ts`)
- Database query abstraction
- Parameterized SQL queries
- Result mapping to TypeScript types

## 3. Database Queries

### 3.1 Repository Pattern

**CandidateRepository Example:**
```typescript
export class CandidateRepository {
  async findAll(page: number, limit: number): Promise<Candidate[]> {
    const offset = (page - 1) * limit;
    const query = `
      SELECT * FROM candidates 
      ORDER BY created_at DESC 
      LIMIT ? OFFSET ?
    `;
    const [rows] = await pool.execute(query, [limit, offset]);
    return rows as Candidate[];
  }
  
  async findById(id: string): Promise<Candidate | null> {
    const query = 'SELECT * FROM candidates WHERE id = ?';
    const [rows] = await pool.execute(query, [id]);
    return rows.length > 0 ? rows[0] : null;
  }
  
  async create(data: Partial<Candidate>): Promise<Candidate> {
    const query = `
      INSERT INTO candidates 
      (id, name, email, status, created_at)
      VALUES (UUID(), ?, ?, ?, NOW())
    `;
    await pool.execute(query, [data.name, data.email, data.status || 'new']);
    return this.findByEmail(data.email!);
  }
  
  async update(id: string, data: Partial<Candidate>): Promise<void> {
    const updates = Object.entries(data)
      .filter(([_, value]) => value !== undefined)
      .map(([key]) => `${key} = ?`)
      .join(', ');
    
    const values = Object.entries(data)
      .filter(([_, value]) => value !== undefined)
      .map(([_, value]) => value);
    
    const query = `UPDATE candidates SET ${updates}, updated_at = NOW() WHERE id = ?`;
    await pool.execute(query, [...values, id]);
  }
  
  async delete(id: string): Promise<void> {
    const query = 'DELETE FROM candidates WHERE id = ?';
    await pool.execute(query, [id]);
  }
}
```

## 5. Security Implementation

### 5.1 Authentication Middleware

```typescript
export const authenticateToken = (
  req: express.Request,
  res: express.Response,
  next: express.NextFunction
) => {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];
  
  if (!token) {
    return res.status(401).json({ error: 'No token provided' });
  }
  
  jwt.verify(token, process.env.JWT_SECRET!, (err, user) => {
    if (err) {
      return res.status(403).json({ error: 'Invalid token' });
    }
    req.user = user;
    next();
  });
};
```

### 5.2 Role-Based Access Control

```typescript
export const authorize = (roles: string[]) => {
  return (req: express.Request, res: express.Response, next: express.NextFunction) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({ error: 'Insufficient permissions' });
    }
    next();
  };
};
```
